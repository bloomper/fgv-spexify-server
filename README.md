# Spexify Server

## Overview

Spexify Server is the backend of Spexify, FGV's music service for the songs the spex have recorded over the years.
It is a Spring Boot application with a GraphQL API, plain HTTP endpoints for audio, downloads, covers and resumable
(tus) uploads, and a gateway to [Navidrome][1] for Subsonic apps. It uses MySQL, Keycloak ([fgv-keycloak][2]) and
Spexregister, which it reads spex from with the `MEDIA` role. [Spexify Web][3] is its frontend and
[fgv-spexify-deploy][4] runs it. The product spec is in [fgv-spexify-spec][5].

## How it fits together

- **The catalogue** (albums linked to spex, tracks) lives in MySQL. Audio files and covers live in the media folder,
  named by id, never in the database:

  | Folder         | Content                                 | Navidrome sees it |
  |----------------|-----------------------------------------|-------------------|
  | `music/`       | Published tracks and their covers       | Yes, read-only    |
  | `unpublished/` | Unpublished tracks                      | No                |
  | `trash/`       | Trashed tracks                          | No                |
  | `covers/`      | Every album's cover                     | No                |
  | `uploads/`     | Unfinished uploads (kept 24 hours)      | No                |

- **Tags.** When a track enters `music/`, or its metadata changes there, ffmpeg writes the tags, with the track's and
  album's uuids as MusicBrainz release track id and album id. Navidrome derives its persistent ids from those, so
  editing a title keeps stars and playlists. MP4 files cannot carry them through ffmpeg; Navidrome then falls back to
  album, disc, number and title. Lyrics are written beside the file as `.lrc` or `.txt`.
- **Scans.** After a change the server asks Navidrome to scan, then matches Navidrome's song ids to tracks by the
  uuid in the path (`ND_SUBSONIC_DEFAULTREPORTREALPATH=true`).
- **The gateway** (`/rest/**`) authenticates an app password (`u` with `p`, or `t` and `s`), an OpenSubsonic API key
  or a Keycloak token, re-checks the user's `USER` role in Keycloak (cached ten minutes), refuses operations that
  change the library or users, and forwards the request to Navidrome with `Remote-User`. Navidrome creates users only
  when its web index is opened with that header, so the gateway does that once per user. Navidrome must trust only
  this server's address (`ND_EXTAUTH_TRUSTEDSOURCES`).
- **App passwords** are stored encrypted with AES-GCM (`APP_PASSWORD_KEY`, 32 bytes base64), because Subsonic's token
  login needs the password; API keys only as SHA-256.

## Running locally

Keycloak comes from `fgv-infra-deploy/local`, with the realm's `fgv-spexify` and `fgv-spexify-service` clients.
`docker-compose.yaml` here starts MySQL and Navidrome:

```shell
docker compose up -d
API_KEYCLOAK_SERVICE_CLIENT_SECRET=… API_KEYCLOAK_ADMIN_CLIENT_SECRET=… \
API_IMPORT_SAMPLE_DATA=true \
JAVA_TOOL_OPTIONS="-Djavax.net.ssl.trustStore=<a truststore with the local Caddy CA>" \
./gradlew bootRun --args='--spring.profiles.active=local'
```

The API listens on 8082. ffmpeg and ffprobe must be on the path.

### Sample data

With `API_IMPORT_SAMPLE_DATA=true` the API replaces the database and empties the media folders at every start (it
refuses in the `production` profile), then builds albums on Spexregister's sample spex with audio generated by ffmpeg
in every accepted format. `API_SAMPLE_DATA_SIZE=large` makes about 300 albums.

Test credentials (password `SAMPLE_USER_PASSWORD`, default `s3cr3t-s3cr3t`):

| User                        | Roles on `fgv-spexify`          |
|-----------------------------|---------------------------------|
| `spexify-user@fgv.nu`       | `USER`                          |
| `spexify-editor@fgv.nu`     | `USER`, `EDITOR`                |
| `spexify-admin@fgv.nu`      | `USER`, `ADMIN`                 |
| `spexify-no-access@fgv.nu`  | none                            |
| `spexify-spexflix@fgv.nu`   | `USER`, and `USER` on Spexflix  |
| `admin@fgv.nu`              | `USER`, `ADMIN` (Spexregister's sample admin) |

`spexify-user@fgv.nu` has the app password `SAMPLE_APP_PASSWORD` (default `sample-app-password-0001`) and an expired
one. Spexregister deletes all Keycloak users when it imports its sample data, so restart Spexify after it.

## Building from source

Java 25, ffmpeg for the media tests, and Docker for the integration tests:

```
./gradlew test              # unit tests
./gradlew check             # unit and integration tests
./gradlew bootJar           # build/libs/app.jar, which the Dockerfile packs with ffmpeg
```

## Published images

CI builds the image from the `Dockerfile` (not with Jib: the API needs ffmpeg) and publishes
`bloomper/fgv-spexify-server` for `linux/amd64` and `linux/arm64`:

| Trigger              | Tags                              |
|----------------------|-----------------------------------|
| push to `develop`    | `develop`, `sha-<commit>`         |
| push of tag `vX.Y.Z` | `X.Y.Z`, `latest`, `sha-<commit>` |
